# 灵犀 AI — 产品与 UI 固定方案 v1.0

## 产品表达

- 产品名：**灵犀 AI**
- 产品类别：**AI Sales OS**
- 定位：面向企业销售全生命周期的 AI 智能平台
- 核心承诺：懂客户、懂销售、懂业务，给出每一步最佳行动
- 愿景：让 AI 参与每一次销售决策
- 设计原则：**AI 在幕后，专业在台前**

AI 不以机器人、聊天首页或炫技动画出现。它通过建议、提醒、证据、风险和自动化结果融入既有销售工作流。

## 信息架构

1. 产品预览：移动端助手、PC 会话助手
2. 运营工作台：经营看板、会话中心、NBA 建议记录、跟进任务
3. AI 与知识：知识库、场景与策略、质量评测、提示词版本
4. 客户经营：客户与画像、CRM 同步、分析报表
5. 系统管理：成员与权限、渠道与集成、安全审计、全局设置

## 核心交互模型

闭环固定为：`Data → Insight → Decision → NBA → Action → Result → Learning`。

销售端 NBA 卡片包含分析范围说明、已获取关键字段、可直接执行的 NBA、置信度，以及采纳、修改、拒绝、稍后处理四种动作。对外发送必须人工确认。不要使用“建议话术”标签，卡片正文直接展示生成的 NBA；不在销售端展示原始对话、命中场景、知识依据或引用来源，这些信息只保留在后台审计记录中。

退款、签约、敏感承诺、越权操作、知识不足和低置信度场景不生成可直接发送的话术，统一进入人工接管。

### 移动端 NBA 触发规则

- 客户消息不自动触发 NBA，允许客户将一个意图拆成多条消息表达。
- 由销售主动点击“调用 AI 分析本轮对话”，避免高频建议干扰会话。
- 本轮分析窗口从“上一次 AI 辅助回复发送完成”之后开始，覆盖期间全部客户和销售消息。
- AI 辅助回复包括“直接采纳后发送”和“修改后发送”，统计及审计中必须分别记录为 `accepted` 与 `edited`。
- 销售自行输入的回复记录为 `human`，不会重置 AI 辅助回复统计口径。
- AI 每次生成 NBA 时，合并历史客户字段并抽取本轮新增字段；新增或变化字段需要突出回显。
- 修改 NBA 采用卡片内联编辑，不使用阻塞会话的模态框。编辑期间的新客户消息继续实时进入会话区。
- NBA 默认高度应控制在移动端首屏可快速扫读的范围内；正文超过三行时截断，销售可通过“修改”查看完整内容。
- 修改 NBA 期间收到客户新消息时，编辑器自动折叠为“收到客户新消息”状态条，优先让出会话视野；点击状态条恢复编辑，已编辑内容不得丢失。

## 排版与布局

- 字体：Inter / SF Pro Display / PingFang SC / Microsoft YaHei
- 页面标题 24px，卡片标题 14px，正文 14px，辅助文字 12px，标签 11px
- PC 主导航 232px；顶部栏 64px；内容区最大宽度 1540px
- 卡片圆角 12px；控件圆角 8px；使用 8px 基础间距体系
- 卡片只使用 1px `#E9E9EE` 边框和极轻阴影

## 页面固定方案

### 移动端

保持企业微信原生会话心智。AI 只在有价值动作时出现轻量状态条和 NBA 卡片。建议采纳后进入输入框，由销售发送。

### PC 端

固定三栏：客户队列 / 原生会话 / AI 销售副驾。副驾依次展示客户画像、购买信号、历史轨迹、NBA、跟进待办，不采用聊天机器人形态。

### 管理后台

首页只展示 NBA 采纳率、回答准确率、问题解决率、平均响应时间等业务指标。其余页面围绕运营、知识、质量、客户和治理组织。

## 动效与状态

- 常规过渡 150–250ms，只用于悬停、选中、抽屉和提示
- 禁止持续发光、循环动画和大幅视差
- AI 分析中使用静态轻提示，不使用机器人头像
- 成功、风险和高风险必须同时使用文字，不仅依赖颜色

## 研发验收基线

- 适配 375、390、768、1280、1440、1920px
- 核心操作具备键盘焦点及 hover / active / disabled 状态
- 对比度遵守 WCAG AA
- 列表具备加载、空状态、错误、无权限和分页状态
- NBA 生成、修改、发送、拒绝、转人工、CRM 写回全部进入审计日志
- UI 不展示虚构 AI 能力；置信度和依据必须来自真实接口数据
